# Signals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Orbit Flo a personal notification inbox fed by database triggers, plus the `@`-mention feature that supplies one of its event types.

**Architecture:** A `public.signals` table holds one row per notification, addressed to a recipient. Every row is written by a trigger, never by application code, so no write path can forget. The client reads with TanStack Query on load and focus — no realtime. Mentions are stored as ordinary markdown (`[@Name](orbit:user/<uuid>)`) and a trigger extracts them from note and comment bodies.

**Tech Stack:** Postgres 15 + Supabase RLS, React 19, Vite, Tailwind v4, TanStack Query v5, react-markdown, Vitest, Playwright.

## Global Constraints

- Migrations live in `supabase/migrations/` and are applied by the **user** running `npx supabase db push` from the worktree. Never attempt to apply one yourself.
- Every security-definer function must `set search_path = public, pg_temp`, and every `revoke` must name **both** `public` and `anon` (see `202608130001`) — revoking from `PUBLIC` alone leaves Supabase's default grant to `anon` intact.
- `SignalsPage` **must** be lazy-loaded via `src/app/route-loaders.ts`. A non-lazy route pulls the real Supabase client into `App.test.tsx`, which throws without env vars: green locally, red in CI.
- Every new shell-level query **must** be seeded in `createVisualQueryClient` in `src/dev/orbit-flo-visual-review.tsx`, or the visual-review route's zero-Supabase-calls assertion fails.
- The unread marker must **not** be cyan. In this design language cyan means interactive; unread is a state.
- Commit trailer on every commit: `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
- Run the suite with `npm test -- --maxWorkers=2`.

## Deviation from the spec, and why

The spec says `extractOrbitLinks` gains a `user` kind and `saveNoteLinks` filters it out with a test pinning the filter.

**This plan instead keeps mentions in a separate module** (`src/features/links/mention.ts`) and leaves `orbit-link.ts`, `LinkKind`, `saveNoteLinks`, `targetColumnFor` and `backlinksQueryKey` completely untouched.

Same goal, stronger guarantee. The spec's concern was mentions leaking into `note_links`, which has no column for a user. A filter guards that with a test; a separate module makes it **unrepresentable** — `saveNoteLinks` never sees a user link because the function it calls cannot produce one. `LinkKind` also stays a closed three-value union, so `targetColumnFor` remains exhaustive without a widening cast.

```sql
-- One row per notification, addressed to a recipient. Written only by triggers:
-- a notification you sometimes get is worse than none, and application code has
-- already proven it forgets (linkMention had to be taught to call saveNoteLinks).

create type public.signal_kind as enum (
  'assigned', 'unassigned', 'commented', 'mentioned',
  'invitation_accepted', 'role_changed', 'removed_from_workspace'
);

create table public.signals (
  id            uuid primary key default gen_random_uuid(),
  workspace_id  uuid not null references public.workspaces(id) on delete cascade,
  -- auth.users, not profiles: always the current user, never embedded. Pointing
  -- both user columns at profiles would give this table two foreign keys to it
  -- and make the profiles(...) embed ambiguous.
  recipient_id  uuid not null references auth.users(id) on delete cascade,
  -- profiles, so the list can embed profiles(display_name) for "Alice assigned
  -- you...". This is the relationship whose absence broke Settings in #48.
  actor_id      uuid references public.profiles(id) on delete set null,
  kind          public.signal_kind not null,
  work_item_id  uuid,
  note_id       uuid,
  comment_id    uuid references public.work_item_comments(id) on delete cascade,
  read_at       timestamptz,
  created_at    timestamptz not null default now(),
  foreign key (work_item_id, workspace_id)
    references public.work_items(id, workspace_id) on delete cascade,
  foreign key (note_id, workspace_id)
    references public.notes(id, workspace_id) on delete cascade
);

-- comment_id is a plain reference: work_item_comments has only a primary key on
-- id, with no (id, workspace_id) unique to hang a composite key on.

create index signals_recipient_unread_idx
  on public.signals (recipient_id, read_at, created_at desc);

alter table public.signals enable row level security;

-- No insert grant and no insert policy: triggers own creation, the same
-- deliberate gap as workspace_members and workspace_invitations.
grant select, delete on public.signals to authenticated;
grant update(read_at) on public.signals to authenticated;

create policy "Recipients can view their signals"
on public.signals
for select
to authenticated
using (
  recipient_id = (select auth.uid())
  and private.is_workspace_member(workspace_id)
);

create policy "Recipients can mark their signals read"
on public.signals
for update
to authenticated
using (
  recipient_id = (select auth.uid())
  and private.is_workspace_member(workspace_id)
)
with check (
  recipient_id = (select auth.uid())
  and private.is_workspace_member(workspace_id)
);

create policy "Recipients can delete their signals"
on public.signals
for delete
to authenticated
using (
  recipient_id = (select auth.uid())
  and private.is_workspace_member(workspace_id)
);

-- Prove the grants are what we think. A REVOKE or GRANT that changes nothing is
-- silent, so assert rather than assume.
do $$
begin
  if has_table_privilege('authenticated', 'public.signals', 'INSERT') then
    raise exception 'authenticated can insert signals directly; triggers must own creation';
  end if;
  if not has_table_privilege('authenticated', 'public.signals', 'SELECT') then
    raise exception 'authenticated cannot read signals';
  end if;
end
$$;
```

## Task 2: Assignment triggers

**Files:**
- Create: `supabase/migrations/202608180002_signal_triggers.sql`

**Interfaces:**
- Consumes: `public.signals` from Task 1.
- Produces: `private.signal_assignment()` and trigger `work_items_signal_assignment`.

- [ ] **Step 1: Write the trigger**

```sql
-- Assignment is the clearest "this is now your problem" event, and the one the
-- assignment feature left dangling: assigned_to records who is assigned now,
-- never that it changed or by whom.
create or replace function private.signal_assignment()
returns trigger
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  actor uuid := (select auth.uid());
begin
  -- `is not distinct from`, never `=`. assigned_to moves to and from null
  -- constantly, and null = null is null, not true, so a plain equality test
  -- would let a no-op update raise a signal.
  if tg_op = 'UPDATE' and new.assigned_to is not distinct from old.assigned_to then
    return new;
  end if;

  -- `old` may only be touched on UPDATE; referencing it during INSERT raises.
  if tg_op = 'UPDATE'
     and old.assigned_to is not null
     and old.assigned_to is distinct from actor then
    insert into public.signals
      (workspace_id, recipient_id, actor_id, kind, work_item_id)
    values
      (new.workspace_id, old.assigned_to, actor, 'unassigned', new.id);
  end if;

  -- `is distinct from actor` rather than `<> actor`: when actor is null (a
  -- service-role or SQL-editor write) `<>` yields null and the signal would be
  -- silently dropped.
  if new.assigned_to is not null
     and new.assigned_to is distinct from actor then
    insert into public.signals
      (workspace_id, recipient_id, actor_id, kind, work_item_id)
    values
      (new.workspace_id, new.assigned_to, actor, 'assigned', new.id);
  end if;

  return new;
end;
$$;

create trigger work_items_signal_assignment
after insert or update of assigned_to on public.work_items
for each row execute function private.signal_assignment();
```

```sql
-- Recipients are the task's assignee and its creator. `union` deduplicates, so
-- a task whose assignee is also its creator produces one row, not two.
create or replace function private.signal_comment()
returns trigger
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  actor uuid := (select auth.uid());
begin
  insert into public.signals
    (workspace_id, recipient_id, actor_id, kind, work_item_id, comment_id)
  select new.workspace_id, r.recipient, actor, 'commented', new.work_item_id, new.id
  from (
    select w.assigned_to as recipient
      from public.work_items w where w.id = new.work_item_id
    union
    select w.created_by
      from public.work_items w where w.id = new.work_item_id
  ) r
  where r.recipient is not null
    and r.recipient is distinct from actor;

  return new;
end;
$$;

create trigger work_item_comments_signal
after insert on public.work_item_comments
for each row execute function private.signal_comment();
```

- [ ] **Step 2: Write the membership triggers**

```sql
create or replace function private.signal_role_change()
returns trigger
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  actor uuid := (select auth.uid());
begin
  if new.role is not distinct from old.role then
    return new;
  end if;

  if new.user_id is distinct from actor then
    insert into public.signals (workspace_id, recipient_id, actor_id, kind)
    values (new.workspace_id, new.user_id, actor, 'role_changed');
  end if;

  return new;
end;
$$;

create trigger workspace_members_signal_role
after update of role on public.workspace_members
for each row execute function private.signal_role_change();

create or replace function private.signal_removal()
returns trigger
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  actor uuid := (select auth.uid());
begin
  -- Leaving voluntarily is not news to the person who left.
  if old.user_id is not distinct from actor then
    return old;
  end if;

  -- The membership may be disappearing because the ACCOUNT is being deleted, in
  -- which case the recipient foreign key would fail or immediately cascade. It
  -- also matters for the e2e teardown, which deletes its throwaway accounts.
  if not exists (select 1 from auth.users u where u.id = old.user_id) then
    return old;
  end if;

  insert into public.signals (workspace_id, recipient_id, actor_id, kind)
  values (old.workspace_id, old.user_id, actor, 'removed_from_workspace');

  return old;
end;
$$;

create trigger workspace_members_signal_removal
after delete on public.workspace_members
for each row execute function private.signal_removal();

-- The recipient is the INVITER. Whoever clicked Accept already knows; the
-- person currently learning nothing is the one who sent it.
create or replace function private.signal_invitation_accepted()
returns trigger
language plpgsql
security definer
set search_path = public, pg_temp
as $$
begin
  if new.invited_by is not null
     and new.invited_by is distinct from new.accepted_by then
    insert into public.signals (workspace_id, recipient_id, actor_id, kind)
    values (new.workspace_id, new.invited_by, new.accepted_by, 'invitation_accepted');
  end if;

  return new;
end;
$$;

create trigger workspace_invitations_signal_accepted
after update on public.workspace_invitations
for each row
when (old.accepted_at is null and new.accepted_at is not null)
execute function private.signal_invitation_accepted();
```

```ts
import type { SignalKind } from "../../lib/supabase/database.types";

export type SignalSentenceInput = {
  kind: SignalKind;
  actorName: string | null;
  targetTitle: string | null;
};

/**
 * Every branch of the inbox copy lives here, so the one part of this feature
 * with real branching is testable without a database.
 */
export function buildSignalSentence({
  kind,
  actorName,
  targetTitle,
}: SignalSentenceInput): string {
  // actor_id is `on delete set null`: a departed colleague leaves a null, and
  // "Someone" is honest where a blank would look like a rendering bug.
  const actor = actorName ?? "Someone";

  switch (kind) {
    case "assigned":
      return `${actor} assigned you ${targetTitle ?? "a deleted task"}`;
    case "unassigned":
      return `${actor} unassigned you from ${targetTitle ?? "a deleted task"}`;
    case "commented":
      return `${actor} commented on ${targetTitle ?? "a deleted task"}`;
    case "mentioned":
      return `${actor} mentioned you in ${targetTitle ?? "a deleted note"}`;
    case "invitation_accepted":
      return `${actor} accepted your invitation`;
    case "role_changed":
      return `${actor} changed your role`;
    case "removed_from_workspace":
      return `${actor} removed you from this workspace`;
  }
}
```

```ts
import type { SupabaseClient } from "@supabase/supabase-js";
import type { Database, SignalKind } from "../../lib/supabase/database.types";

type Client = SupabaseClient<Database>;

export type Signal = {
  id: string;
  kind: SignalKind;
  createdAt: string;
  readAt: string | null;
  actorName: string | null;
  workItemId: string | null;
  noteId: string | null;
};

export const signalsQueryKey = (workspaceId: string) => ["signals", workspaceId] as const;

export const unreadSignalCountQueryKey = (workspaceId: string) =>
  ["signals", "unread-count", workspaceId] as const;

/** Not workspace-scoped on purpose: this feeds the switcher dot. */
export const unreadByWorkspaceQueryKey = ["signals", "unread-by-workspace"] as const;

const listLimit = 50;

export async function listSignals(client: Client, workspaceId: string): Promise<Signal[]> {
  const { data, error } = await client
    .from("signals")
    .select("id, kind, created_at, read_at, work_item_id, note_id, profiles(display_name)")
    .eq("workspace_id", workspaceId)
    .order("created_at", { ascending: false })
    .limit(listLimit);

  if (error) throw error;

  return ((data ?? []) as unknown as Array<{
    id: string;
    kind: SignalKind;
    created_at: string;
    read_at: string | null;
    work_item_id: string | null;
    note_id: string | null;
    profiles: { display_name: string } | null;
  }>).map((row) => ({
    id: row.id,
    kind: row.kind,
    createdAt: row.created_at,
    readAt: row.read_at,
    actorName: row.profiles?.display_name ?? null,
    workItemId: row.work_item_id,
    noteId: row.note_id,
  }));
}

export async function countUnreadSignals(client: Client, workspaceId: string): Promise<number> {
  const { count, error } = await client
    .from("signals")
    .select("id", { count: "exact", head: true })
    .eq("workspace_id", workspaceId)
    .is("read_at", null);

  if (error) throw error;
  return count ?? 0;
}

/**
 * "My unread everywhere" by construction: RLS already restricts signals to
 * recipient_id = auth.uid(), so no filter and no RPC are needed. Counted in the
 * client because PostgREST has no group-by.
 */
export async function unreadCountsByWorkspace(client: Client): Promise<Map<string, number>> {
  const { data, error } = await client.from("signals").select("workspace_id").is("read_at", null);

  if (error) throw error;

  const counts = new Map<string, number>();
  for (const row of (data ?? []) as Array<{ workspace_id: string }>) {
    counts.set(row.workspace_id, (counts.get(row.workspace_id) ?? 0) + 1);
  }

  return counts;
}

export async function markSignalRead(client: Client, input: { id: string }) {
  const { error } = await client
    .from("signals")
    .update({ read_at: new Date().toISOString() })
    .eq("id", input.id);

  if (error) throw error;
}

export async function markAllSignalsRead(client: Client, input: { workspaceId: string }) {
  const { error } = await client
    .from("signals")
    .update({ read_at: new Date().toISOString() })
    .eq("workspace_id", input.workspaceId)
    .is("read_at", null);

  if (error) throw error;
}
```

```ts
/**
 * Mentions deliberately live outside orbit-link.ts. LinkKind stays a closed
 * union of note | task | project, so saveNoteLinks and targetColumnFor cannot
 * receive a user link that note_links has no column for.
 */
export const mentionHrefPattern =
  /^orbit:user\/([0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12})$/;

const TRIGGER = "@";

/** Brackets in a name would terminate the markdown link early. */
function safeLabel(label: string) {
  return label.replaceAll("[", "(").replaceAll("]", ")");
}

export function formatMention(userId: string, displayName: string): string {
  return `[@${safeLabel(displayName)}](orbit:user/${userId})`;
}

export function findMentionTrigger(
  body: string,
  caret: number,
): { start: number; query: string } | null {
  const before = body.slice(0, caret);
  const start = before.lastIndexOf(TRIGGER);
  if (start === -1) return null;

  // Word boundary: start of body, or preceded by whitespace. Without this,
  // typing any email address opens the mention picker.
  const preceding = start === 0 ? "" : before[start - 1];
  if (preceding !== "" && !/\s/.test(preceding)) return null;

  const query = before.slice(start + TRIGGER.length);

  // A newline or a closing bracket means the trigger was abandoned.
  if (/[\n\]]/.test(query)) return null;

  return { start, query };
}
```

```ts
import { findMentionTrigger } from "./mention";

export type ActiveTrigger = { kind: "link" | "mention"; start: number; query: string };

/**
 * One picker, two sources. Whichever trigger starts later is the one the caret
 * is actually inside.
 */
export function findTrigger(body: string, caret: number): ActiveTrigger | null {
  const link = findLinkTrigger(body, caret);
  const mention = findMentionTrigger(body, caret);

  if (link && mention) {
    return mention.start > link.start
      ? { kind: "mention", ...mention }
      : { kind: "link", ...link };
  }
  if (link) return { kind: "link", ...link };
  if (mention) return { kind: "mention", ...mention };
  return null;
}
```

## Task 12: Mention trigger

**Files:**
- Create: `supabase/migrations/202608180003_mention_triggers.sql`

- [ ] **Step 1: Write the trigger**

```sql
-- Mentions are extracted in SQL rather than by the client, for the same reason
-- every other signal is: a trigger fires on every write path, including the
-- edit made a week later. find_unlinked_mentions already does regex work here,
-- so this follows an established house pattern.
create or replace function private.signal_mentions()
returns trigger
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  actor      uuid := (select auth.uid());
  old_body   text := '';
  mentioned  uuid;
begin
  if tg_op = 'UPDATE' then
    old_body := coalesce(old.body, '');
  end if;

  for mentioned in
    select distinct (m[1])::uuid
    from regexp_matches(
      coalesce(new.body, ''),
      'orbit:user/([0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12})',
      'g'
    ) as m
  loop
    -- Already present before this edit: notifying again would mean every
    -- subsequent edit re-notifies everyone named in the body. Conservative by
    -- design — it errs towards silence, never towards repetition.
    continue when position(mentioned::text in old_body) > 0;

    continue when mentioned is not distinct from actor;

    -- security definer bypasses RLS, so membership is checked explicitly. A
    -- pasted or stale uuid otherwise creates rows nobody can ever read.
    continue when not exists (
      select 1 from public.workspace_members wm
      where wm.workspace_id = new.workspace_id and wm.user_id = mentioned
    );

    if tg_table_name = 'notes' then
      insert into public.signals
        (workspace_id, recipient_id, actor_id, kind, note_id)
      values (new.workspace_id, mentioned, actor, 'mentioned', new.id);
    else
      insert into public.signals
        (workspace_id, recipient_id, actor_id, kind, work_item_id, comment_id)
      values (new.workspace_id, mentioned, actor, 'mentioned', new.work_item_id, new.id);
    end if;
  end loop;

  return new;
end;
$$;

create trigger notes_signal_mentions
after insert or update of body on public.notes
for each row execute function private.signal_mentions();

create trigger work_item_comments_signal_mentions
after insert or update of body on public.work_item_comments
for each row execute function private.signal_mentions();
```
